# Changelog

Dated log of notable milestones — not a commit-by-commit history (see `git log` for that once the repo is under version control). Append new entries at the top. One entry per milestone, not per file changed.

Format: `YYYY-MM-DD — <what changed> — <why it matters>`

---

- **2026-07-31** — "Backend: full completion pass" (plan: see `.ai/memory/decisions.md` context if needed, or the session transcript). Five things landed together:
  1. **New `apps/worker` service** — an independent Spring Boot project (own Gradle wrapper, `com.projectgenerator.worker` root package) with no REST layer, only a Redis Streams consumer. `apps/api`'s `GeneratorServiceImpl` now just persists a `QUEUED` `GenerationJobEntity` and `XADD`s to a `generation-jobs` stream — the old `@Async processGenerationAsync` method (and the self-invocation bug it had) is deleted, not patched. `apps/worker`'s `GenerationJobConsumer`/`GenerationJobProcessor` do the real work: reload the job (skip if already terminal — the idempotency guard), call an AI provider, render a template, build the AI's code into the tree, zip it, create the project row, mark the job complete. `GenerationJobEntity`/`ProjectEntity` are duplicated (not shared) between `apps/api` and `apps/worker` — deliberate, since there's no root-level multi-project Gradle build to hang a shared module off yet; tracked in `known-issues.md`.
  2. **`provider/` and `archive/` packages moved from `apps/api` to `apps/worker`** wholesale (deleted from `apps/api`, not duplicated — nothing there calls them anymore). `apps/api` also lost its now-dead `commons-compress`/`commons-io` dependencies and `StorageService.storeArchive` (unused once `apps/worker` started writing archive files directly).
  3. **OpenAI and Anthropic are real now**, not just Gemini — all three extend a new `AbstractRestAiProvider` base (shared timeout/RestClient construction + api-key-guard + error wrapping) to avoid tripling the near-identical structure the earlier code review flagged.
  4. **Real multi-file template rendering** for the Spring Boot stack: `templates/spring-boot/template.json` + `files/` (a small, genuinely buildable Gradle+Spring Boot skeleton with a `__PACKAGE_PATH__` token for the one dynamic path segment), rendered by a new `TemplateEngine` in `apps/worker`. The AI's generated code is written into the templated tree as one extra file, not the entire output — matching `packages/template-engine/PROCESS.md`'s own diagram. `packages/template-engine` itself stays docs-only by design (see `known-issues.md` #7) — the real implementation lives in `apps/worker` since nothing Node-based would ever consume a TS version of it.
  5. **Admin read endpoints** (`AdminController`: `/api/v1/admin/users`, `/jobs`, `/stats`, all already `ROLE_ADMIN`-gated) added to `apps/api`, plus `application-prod.yml` for both `apps/api` and `apps/worker` (no inline secret defaults).

  Several code-review findings from the earlier pass got resolved as a side effect (not targeted deliberately) — see `known-issues.md` #10 for the list. `apps/web` was not touched — still on mock data. Both projects compile clean (`./gradlew.bat compileJava`); the Redis Streams wiring has not been live-tested against a running Redis yet.
- **2026-07-31** — Wired the generation pipeline end-to-end for one provider (backend only): `GenerationJobEntity`/`GenerationJobRepository` replace the in-memory job map in `GeneratorServiceImpl` (jobs now persist to the existing `generation_jobs` table and survive a restart); `GeminiAiProvider` now makes a real HTTP call to the Gemini Generative Language API instead of returning a hardcoded string (fails the job with a clear error if `GEMINI_API_KEY` is unset, rather than faking success); the AI's real output is written to a per-job workspace under `generated/<jobId>/`, zipped via the previously-orphaned `ArchiveService`, stored via `StorageService`, and the resulting URL is attached to the project through a new internal-only `ProjectService.updateArchiveUrl`. `OpenAiProvider`/`AnthropicAiProvider` remain stubs (out of scope for this pass), and the workspace built is still a minimal AI-output wrapper, not the full multi-file template render planned for `packages/template-engine` (`../context/roadmap.md` Phase 2). The `apps/web` frontend was not touched — it's still on mock data.
- **2026-07-31** — Fixed all 7 Critical findings from a backend security review of `apps/api`: `SecurityConfig` no longer permits every request (`anyRequest().authenticated()`); CORS restricted from `*`+credentials to a configurable origin allowlist (`cors.allowed-origins`); `JwtTokenProvider`'s hardcoded JWT-secret fallback removed (fails fast if `jwt.secret` isn't set) and the dev-profile default rotated; `ProjectController.createProject` no longer trusts the spoofable `X-User-Id` header, derives the user from the authenticated JWT principal instead; added ownership checks so `GET/PATCH/DELETE /api/v1/projects/{id}` and `GET /api/v1/generator/jobs/{jobId}` reject requests from a user who doesn't own the resource (closes two IDORs); generation job ids switched from a truncated 8-char UUID fragment to a full UUID (removes a collision/guessability risk); `LocalStorageServiceImpl` archive downloads now reject any filename that resolves outside the configured storage directory (closes a path-traversal). 24 remaining High/Medium/Low findings from the same review are logged in `known-issues.md` #10, not yet fixed.
- **2026-07-31** — `.ai/` restructured into `architecture/`, `standards/`, `context/`, `templates/`, `memory/` (this changelog included) — establishes the durable-knowledge structure this file and its siblings now follow, replacing the earlier flat/aspirational `.ai/AGENT.md` that referenced files that didn't exist.
- **2026-07-31** — Baseline code-vs-docs audit completed — confirmed real, working auth/CRUD backend (Spring Boot, 47 source files) and a built Next.js UI shell (105 source files), but found the AI generation pipeline is simulated and the frontend runs entirely on mock data. Full findings in `known-issues.md`.
